# Phase 18：操作台布局 + 状态行

不是功能，是「功能变多之后界面开始挤」的第一次偿还。

---

## 问题：顶栏挤爆了

做完 12 个 A 类功能后，顶栏变成了这样：

```
3%   每次询问   计划   分支   目录   导出   压缩上下文
```

7 个东西并排。而且这 7 个里**真正高频的只有压缩和权限**，其余一周用一次。

更根本的问题是位置错了：这些都是「对这次发送的设定」，却放在屏幕最上方，而用户的视线和手都在底部输入框。**每改一次权限都要跨越大半个屏幕。**

---

## 做法：把控件收进输入框

```
┌─ 输入框 ────────────────────────────────────────────┐
│ 问点什么…（Enter 发送，Shift+Enter 换行）             │
│                                                      │
│ 每次询问  计划  分支  目录  导出  压缩      [排队] [■] │
└──────────────────────────────────────────────────────┘

◌ 正在执行命令…                              2s · 5.1k tokens
```

顶栏只剩**会话标题 + 上下文占用条**。

这个布局是用户给的参考图里的，比我原本想的「收进 ⋯ 菜单」更好——菜单藏起来的东西用户不会去找，摊在输入框里一眼就能看见。

## 状态行

参考图的 `✻ Running bash...  4m 3s · 225 tok/s` 对应实现：

```
◌ 正在执行命令…                          2s · 5.1k tokens
```

三个信息：

**1. 在干什么。** 引擎只会说 `Working…`，那等于没说。宿主侧记下最近的工具名，翻译成「正在执行命令」「正在读文件」「正在派子任务」。

**2. 跑了多久。** 客户端自己用 `setInterval` 走秒，不靠宿主每秒推 IPC——那样既浪费又会被进程抖动干扰。

**3. token 用量。** 从 `text` 事件的 `agentMeta.usage.totalTokens` 取。

轮结束时状态行**必须消失**，否则界面上会一直挂着「正在执行命令」。

---

## 撞到的两个问题

### 问题 1：工具栏溢出输入框

第一版直接把 7 个控件塞进 `composer`，结果撑破容器、盖住侧栏。

原因：`composer-wrap` 的 `max-width: 720px` 容不下，而 `composer` 没有 `min-width: 0` 所以不收缩。改成 820px + 允许换行。

### 问题 2：权限菜单弹到屏幕外

菜单原本是 `top: 100%`（向下弹）。输入框在屏幕底部，往下弹直接出界。

改成 `bottom: 100%`（向上弹）。

> 这两个都是「把顶栏的东西搬到底部」才会出现的问题——**位置一换，方向性的样式全要重新想**。

### 问题 3（回归）：6 个测试全部找不到按钮

按钮从 `.topbar-action` 改成了 `.bar-action`，测试还在找旧 class，`compact` 和 `dirs` 直接失败。

这是个**必然的代价**：改结构就会打断选择器。但也是好事——它证明测试真的在驱动 UI，而不是空跑。

## 验收

```
状态行: label="正在处理…"  meta="0s"
两秒后 meta: "2s · 5.1k tokens"     ← 时长在走、token 出来了
轮结束后状态行数量: 0                 ← 自动消失
```

**十六个模式全部通过**（`1` / `permission` / `queue` / `resume` / `compact` / `steer` / `diff` / `mode` / `model` / `export` / `task` / `dirs` / `tree` / `image` / `rewind` / `status`），`tsc` 0 错误。

## 已知限制

- 工具栏在窄窗口会换行成两排（可接受，但没做折叠）
- 状态行的 token 是**累计输入**，不是吞吐速率（参考图是 tok/s，我们没算速率）
- 「正在处理」这种笼统描述在模型纯文本生成时仍会出现（那时没有工具名可翻译）
- 侧栏底部的模型名去掉了，单模型时用户看不到当前模型（输入栏有，够用）
